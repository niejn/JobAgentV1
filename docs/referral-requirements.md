# Referral 需求总结（小红书内推通道）

> 本文是讨论沉淀的**需求级总结**（What & Why）；实现方案见 `docs/referral-design.md`（How），
> 执行状态见 `plan.md`。三份文档配套阅读。
>
> 状态：需求已评审确认，进入实施（PR-1 进行中）

---

## 1. 背景与问题

- Boss 直聘海投转化率低，重复劳动大；小红书上有大量**员工发布的内推帖**，
  内推简历直达部门、有真实 HC、回复率高
- 但内推帖有三个天然缺陷：
  1. **没有具体岗位信息**（只有「研发/测试都有」这类大类描述）
  2. **联系方式不在帖内**，触达走评论区/私信
  3. **真假混杂**：大量收费骗局帖和做内推生意的营销号混在其中

## 2. 产品目标

> 候选人配置好简历画像后，系统自动：发现真实员工内推帖 -> 匹配具体岗位 ->
> 起草高回复率的联系话术 -> 在人工确认下完成触达。

核心价值主张：**先找到具体岗位，再联系内推人**——带着「我想投 XX 岗位（附链接）」
去联系，比泛泛的「求内推」回复率显著更高。

## 3. 用户故事

| # | 故事 | 优先级 |
|---|---|---|
| US-1 | 作为求职者，我想搜索小红书上的内推帖并自动提取「哪家公司、什么方向、还有没有效」 | P0 |
| US-2 | 作为求职者，我想让系统把内推帖和我匹配的具体岗位关联起来，联系时能带上岗位链接 | P0 |
| US-3 | 作为求职者，我不想把时间浪费在假内推上，系统要帮我识别骗局帖和内推生意号，**只要真实员工** | P0 |
| US-4 | 作为求职者，我怕账号被封，系统的自动触达必须低频、可控、默认人工确认 | P0 |
| US-5 | 作为求职者，对方回复私信后，我想要一份现成的「岗位资料包」直接复制使用 | P1 |
| US-6 | 作为求职者，我不想重复联系同一个发帖人，也不想用过期帖子 | P1 |

## 4. 功能需求

### FR-1 内推帖发现
- 按关键词搜索小红书笔记（如「XX公司 内推」「内推 社招」），可按目标公司列表过滤
- 抓取每帖：标题、正文、标签、点赞数、发布时间、**评论区内容**（联系方式线索+活跃度）
- 抓取发帖人主页：昵称、简介、IP 属地、**最近 N 篇帖子标题**（账号真实性分析的数据源）
- 帖子超期（默认 >90 天）自动跳过或降权

### FR-2 LLM 结构化提取
- 把帖子+评论解析为结构化 `ReferralOffer`：公司（归一化）、部门/方向、社招/实习/校招、是否有效、投递链接（若有）
- 公司名需归一化（「阿里千问」->「阿里巴巴」），支持别名表 + LLM 判断

### FR-3 岗位交叉匹配（核心差异化能力）
- 匹配来源优先级：A. Boss 直聘按公司抓岗位（v1）｜B. 公司官网 ATS（v2）｜C. 帖内附带的投递链接（v1 顺带）
- 复用现有 LLMMatcher 对 (岗位, 画像) 打分，产出 (offer, job, score) 三元组
- 匹配失败的 offer 降级为「请对方推荐方向内岗位」

### FR-4 触达分级（Human-in-the-Loop）★关键需求
> 动因：XHS 私信是平台风控最强区域（机审扫描内容/外链、批量相似文案判营销号、
> 实测连续只读操作即被限流），全自动私信封号风险高。

| 级别 | 方式 | 默认 | 约束 |
|---|---|---|---|
| L0 评论钩子 | 帖下评论简短求内推，触发**对方私信我** | ✅ | 每日 ≤5 条；LLM 差异化文案；**评论内禁一切链接/联系方式**；分钟级随机间隔 |
| L1 半自动私信 | 草稿推 Telegram，人工确认/粘贴发送 | - | 岗位链接等敏感内容只在人工私信中出现 |
| L2 全自动私信 | Playwright 自动私信 | ❌关闭 | 需双配置开关显式开启；每日 ≤10；分钟级随机间隔；逐条差异化文案；建议非主力号 |

**人工确认检查点（HITL）**：
- CP-1：offer 提取后，Telegram 推摘要，人工可否决（公司错判等）
- CP-2：评论/私信草稿生成后，人工编辑或确认
- CP-3：对方回复后，系统只提醒+提供**岗位资料包**（岗位名+链接+匹配理由+简历要点），人工接管对话

### FR-5 反诈过滤（帖子级 + 账号级）★核心需求
> 目标：只要**真实在该公司工作的员工**，排除内推生意/中介/骗局。

**帖子级（scam_risk）**：话术特征（「不需要经验」「留子友好」「永久 remote」「保证进」）、
帖子 IP 与公司地不符、评论区收费导流 -> 命中即跳过或标记。

**账号级（authenticity，S1-S8 信号）**，核心判据：**真员工只推自己公司**：
- S1 多公司内推（一票否决，直接判 business）｜S2 发帖规律（高频/批量同模板）｜
  S3 用户名/简介营销词｜S4 单公司内容一致性（加分）｜S5 职业痕迹（加分）｜
  S6 IP 属地与公司地一致（加分）｜S7 企业号/认证营销号｜S8 评论区引导加微信收费
- 输出 `authenticity`（employee/recruiter/business/unknown）+ 分数 + 证据列表（供 CP-1 复核）
- 非 employee 或分数 <0.6 不自动触达；unknown 仅出现在报告供人工判断
- 已知副作用（实测）：评论后会引来收费骗局号私信 -> CP-3 提醒用户警惕

### FR-6 通知
- 复用 Telegram/Discord 通道：offer 摘要、草稿、验证码/风控告警、回复提醒

### FR-7 防重复与历史
- 以帖子 id / 作者 id 去重，持久化到 `~/.jobagent/`（不随 CWD 漂移）
- 记录触达状态机：draft -> confirmed -> sent -> skipped/replied

### FR-8 XHS 抓取后端复用（不自研签名）
- 调研结论：采用 **Backend 适配器**模式，`XhsBackend` 协议双实现：
  - `SpiderXhsBackend`（默认）：把 `Spider_XHS` 作为进程内 Python library 直接引入，
    调用其纯 HTTP + 本地 JS 签名能力；与 JobAgent 共用运行环境、日志和 cookie，
    同步接口通过 `asyncio.to_thread()` 接入异步工作流，不使用 subprocess bridge
  - `PlaywrightXhsBackend`（回退）：自研 DOM 解析，无外部依赖
- `SpiderXhsBackend` 只做薄适配和域模型转换：最大化复用 Spider_XHS 的鉴权、签名、
  HTTP 会话、搜索、详情、分页、重试、字段标准化和可用的媒体下载能力，不在 JobAgent
  重复实现；JobAgent 仅负责旅程编排、证据溯源、OCR 和本项目持久化。
- 返回数据统一转为 jobagent 域模型（ReferralPost / AuthorProfile）

## 5. 非功能需求

| 类别 | 需求 |
|---|---|
| 风控安全 | 所有 XHS 写操作可配置每日上限+随机间隔；风控/验证码页检测到即暂停并通知；读操作也要分钟级 pacing |
| 合规 | 自动化违反平台 ToS 的风险已知悉并文档化；仅个人授权范围使用；不存储超出帖子本身的个人信息 |
| 性能 | LLM 提取允许并发但有限流；抓取节奏让位于安全（宁慢勿封） |
| 可维护性 | 平台适配器与业务逻辑解耦（Backend/Extractor/Crossref/Messenger 各自可单测）；新平台（牛客/脉脉）可按同模式扩展 |
| 隐私 | 评论公开暴露求职状态的副作用须在文档与 CLI 提示中明示，提供替代模式 |

## 6. 依赖与前置条件

- XHS 账号（建议非主力小号）+ cookie 登录（`jobagent login --platform xhs`）
- LLM 通道三选一：Claude OAuth（免费复用订阅）/ Anthropic Key / OpenAI Key
- Spider_XHS library 源码路径 + 纳入 JobAgent 环境的 Node.js（PyExecJS 签名）和 curl_cffi 依赖
- 开发环境修复：langchain 版本锁定、playwright chromium（见 plan.md §2）

## 7. 范围外（明确不做）

- 不做：脉脉/牛客等其他渠道（架构预留，暂不实现）
- 不做：自动聊天机器人式跟进（对方回复后一律人工接管）
- 不做：绕过/破解 XHS 风控（检测到即停，不对抗）
- 不做：简历自动投递到邮箱收集类「内推」（骗局特征，直接过滤）

## 8. 验收标准（端到端场景）

1. `jobagent login --platform xhs` 扫码后 cookie 持久化，`--check` 可验证有效性
2. `jobagent referral search --query "内推"` 产出 offer 列表，含公司/方向/有效期/scam_risk/authenticity/证据
3. 多公司内推的账号被标记 business 且不进入触达流程（S1 一票否决验证）
4. `referral run` 对高分 offer：草稿推送到 Telegram（CP-1/CP-2 生效），人工确认前无任何自动写操作
5. 同一帖/同一作者不重复触达；帖子过期自动跳过
6. 全程任一环节触发风控页：立即暂停 + 通知，不重试硬闯
